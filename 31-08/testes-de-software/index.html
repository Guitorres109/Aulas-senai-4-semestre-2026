PARTE 01

Pesquisa sobre Testes de Software

Conceitos fundamentais utilizados para verificar a qualidade e o funcionamento de uma aplicação.

01

O que são testes de software?

Testes de software são procedimentos realizados para verificar se um sistema está funcionando conforme o esperado. Eles ajudam a encontrar erros antes que o sistema seja utilizado pelos usuários.

Exemplo

Verificar se um usuário consegue fazer login utilizando dados válidos.

02

Testes funcionais

Verificam se uma determinada função do sistema realiza aquilo que foi definido nos requisitos. O foco está no comportamento da aplicação.

Exemplo

Testar se o cadastro de um item perdido realmente salva o item no sistema.

03

Testes de regressão

São realizados depois de alterações no sistema para verificar se uma funcionalidade que já funcionava não foi prejudicada.

Exemplo

Depois de alterar o login, verificar se o cadastro de usuários continua funcionando.

04

Testes unitários

Testam pequenas partes do programa de forma isolada, como uma função, método ou componente.

Exemplo

Testar separadamente a função responsável por validar um endereço de e-mail.

05

Testes de integração

Verificam se diferentes partes do sistema conseguem trabalhar corretamente em conjunto.

Exemplo

Verificar se o formulário React envia corretamente os dados para a API e se a API salva essas informações no banco de dados.

06

Técnica de teste caixa-preta

O sistema é testado sem analisar seu código interno. O avaliador observa as entradas e verifica se as saídas correspondem ao esperado.

Exemplo

Inserir uma senha incorreta no login e verificar se o sistema rejeita o acesso.

07

Técnica de teste caixa-branca

Nesse tipo de teste, o código interno é analisado. O objetivo é verificar caminhos, condições, funções e estruturas utilizadas pelo programa.

Exemplo

Analisar no código se o rateLimiter realmente bloqueia o usuário depois de várias tentativas.

PARTE 02

Casos de Teste — Zyrax LOST

Os quatro casos foram definidos com base em funcionalidades importantes da aplicação.

CT01
Cadastro de itens perdidos ou encontrados
Verificar se um usuário consegue cadastrar corretamente um item perdido ou encontrado, preenchendo os campos necessários.
APROVADO
CT02
Cadastro com palavras indevidas
Verificar se o sistema identifica e impede o cadastro de itens contendo palavras inadequadas.
APROVADO
CT03
Muitas tentativas de login — Rate Limiter
Realizar diversas tentativas consecutivas de login para verificar se o mecanismo de proteção contra excesso de requisições funciona corretamente.
APROVADO
CT04
Cadastro de usuário com e-mail existente
Tentar criar uma nova conta utilizando um endereço de e-mail que já está cadastrado.
APROVADO
PARTE 03

Execução dos Testes

Registro dos resultados obtidos durante a execução dos quatro casos de teste.

CT01 APROVADO
O que foi testado Cadastro de itens perdidos ou encontrados.
Resultado esperado O sistema deve permitir o cadastro e disponibilizar o item na plataforma.
Resultado obtido O item foi cadastrado corretamente e ficou disponível no sistema.
CT02 APROVADO
O que foi testado Cadastro de itens contendo palavras indevidas.
Resultado esperado O sistema deve impedir o cadastro ou informar que o conteúdo não é permitido.
Resultado obtido O sistema identificou o conteúdo inadequado e impediu o cadastro.
CT03 APROVADO
O que foi testado RateLimiter da tela de login.
Resultado esperado Depois de várias tentativas, novas requisições devem ser temporariamente limitadas.
Resultado obtido O sistema aplicou a limitação de requisições após várias tentativas consecutivas.
CT04 APROVADO
O que foi testado Cadastro de usuário utilizando um e-mail já existente.
Resultado esperado O sistema deve impedir o cadastro de uma segunda conta com o mesmo e-mail.
Resultado obtido O sistema identificou que o e-mail já estava cadastrado e rejeitou o novo cadastro.

Problemas Encontrados

Registro de problemas observados durante a realização dos testes.

!

Validações de segurança e conteúdo

Durante os testes, foi necessário verificar se as validações de conteúdo e as proteções do sistema estavam sendo aplicadas corretamente. Esses mecanismos são importantes para evitar cadastros inadequados e excesso de requisições.

ATENÇÃO

Como os problemas poderiam ser corrigidos?

Os problemas encontrados devem ser tratados no código responsável pela validação das entradas, autenticação e controle das requisições. Também é importante realizar novos testes após cada correção para garantir que o problema foi resolvido e que nenhuma outra funcionalidade foi afetada.

CONCLUSÃO

A aplicação está funcionando corretamente?

Sim, considerando os testes realizados.

Depois da execução dos quatro casos de teste, consideramos que a aplicação Zyrax LOST está funcionando corretamente nas funcionalidades avaliadas. O cadastro de itens funcionou conforme esperado, conteúdos inadequados foram tratados, o mecanismo de limitação de tentativas do login funcionou e o sistema também impediu o cadastro de usuários com e-mails já existentes.


Entretanto, os resultados não significam que o sistema esteja completamente livre de erros. Foram avaliadas apenas algumas funcionalidades específicas. Para aumentar a confiabilidade da aplicação, seria necessário realizar outros testes, como testes de login, recuperação de senha, pesquisa de itens, upload de imagens, permissões de usuários, responsividade e testes de integração.
